# 運用手順 (イベント当日)

## 1. 事前準備 (前日まで)

1. `.env` を本番設定にする。
   - `HASHTAGS`: 告知に使うハッシュタグと完全に一致させる。表記ゆれがある場合は複数登録する。
     例: `HASHTAGS=myevent2026,マイイベント2026`
   - `EVENT_TITLE` / `EVENT_SUBTITLE`: モニター上部の表示。
   - `ADMIN_TOKEN`: 会場 LAN 上の別端末から管理画面を使うなら必ず設定する。
2. `pnpm build` が通ることを確認する。
3. 開場前の投稿を拾うかを決める。**既定では起動時に取り込みを行いません。**
   当日に管理画面の「受信設定」→「過去の投稿を取り込む」から実行するのが基本で、
   起動と同時に自動で埋めたい場合のみ `STARTUP_BACKFILL_MINUTES` に値を入れる。
4. リハーサル: `HASHTAGS` をテスト用タグにして実際に投稿し、モニターに出るまでの遅延を確認する。
5. 表示確認だけしたい場合は `http://localhost:3000/wall?demo=1` でダミー投稿を流せる。

## 2. モデレーション方針の決定

| モード | 設定 | 向き |
| --- | --- | --- |
| そのまま流す | `MODERATION_MODE=open` | 小〜中規模、身内向け。運営の負荷が低い |
| 承認制 | `MODERATION_MODE=approve` | 公開イベント、企業イベント。運営が 1 名張り付く前提 |

公開イベントでは以下も併せて設定することを推奨します。

```dotenv
MODERATION_MODE=approve
FILTER_LABELED=true
ALLOW_REPLIES=false
NG_WORDS=（イベント固有の禁止語をカンマ区切り）
```

**注意**: ハッシュタグは誰でも使えます。荒らし投稿が会場スクリーンに映る可能性は
技術的にゼロにはできません。規模の大きいイベントでは承認制を既定としてください。

## 3. 当日の起動手順

1. 会場 PC でサーバーを起動する。
   ```bash
   cd bsky-live-wall
   pnpm start
   ```
2. モニター出力側のブラウザで `http://localhost:3000/wall` を開き、**F11 で全画面**にする。
   - ブラウザのスリープ・スクリーンセーバーを無効にしておく。
   - macOS は `caffeinate -d` を併用するとディスプレイスリープを防げる。
3. 運営端末で `http://<会場PCのIP>:3000/admin` を開き、`ADMIN_TOKEN` を入力する。
4. 管理画面の Jetstream 接続状態が「接続中」であることを確認する。

## 4. 進行中の操作

| 状況 | 操作 |
| --- | --- |
| 不適切な投稿が流れた | 管理画面の該当投稿で「非表示」。モニターから即座に消える |
| 特定の荒らしが繰り返す | 「投稿者をブロック」。以降その DID の投稿は表示されない |
| キーワード一致の投稿が画面に出ない | 仕様。管理画面の「承認待ち」で承認すると出る。意図して設定した語なら、その語の設定を「承認なしで表示する」に変える |
| 誤って非表示にした | 「非表示にした投稿」パネルの「復元」で戻す |
| 誤ってブロックした | 「ブロック中の投稿者」パネルの「ブロック解除」。取り下げた投稿もまとめて復元される |
| 登壇者の資料に切り替えたい | 「一時停止」。受信は続くが新規表示を止める。**全ウォールに効く** |
| 特定のモニターだけ内容を変えたい | 管理画面でそのウォールを選び、監視語を変更する |
| 画面をリセットしたい | 「全消去」 |
| タグを間違えて告知した | 「監視設定」で監視対象を変更。表示中の投稿は残るので「全消去」と併用する |
| タグを付け忘れる人が多い | キーワードとして語を追加する。ただし無関係な投稿も拾うため、既定では承認待ちに入る。語ごと・ウォールごとに承認要否を変更できる |
| Jetstream が不安定 | 「監視設定」で接続先を別ホストへ切り替える |
| 荒らしリストを流用したい | 「モデレーションリスト」で自分のリストを取得して購読する |
| 流れた投稿を遡って確認したい | 会場モニター上でマウスホイールを回す。60 秒放置で自動的に最新へ戻る |

## 5. トラブルシューティング

| 症状 | 確認 | 対処 |
| --- | --- | --- |
| 過去の投稿を出したい | - | 管理画面の「受信設定」→「過去の投稿を取り込む」で分数を指定して実行する |
| ウォールを追加したが過去が空 | - | 同上。対象を「選択中のウォールのみ」にして実行する |
| 投稿が全く出ない | 管理画面の統計「一致件数」 | 0 なら `HASHTAGS` の綴りを確認。全角/半角、大文字小文字は自動で吸収される |
| 一致件数は増えるが表示されない | 統計「除外件数」 | NG ワード・リプライ設定・言語設定を確認 |
| Jetstream が「切断」のまま | 会場ネットワーク | WebSocket (443) が塞がれていないか確認。プロキシ環境では別ホストへの切替を試す |
| モニターが「再接続中」から戻らない | サーバープロセス | サーバーが落ちていないか確認。ブラウザは自動再接続するのでサーバー復帰で自然に回復する |
| 表示が重い / カクつく | `WALL_MAX_CARDS` | 値を下げる (12 程度)。`SHOW_IMAGES=false` も有効 |
| アバターや表示名が出ない | AppView 障害 | 投稿表示自体は継続する。放置してよい |

## 6. ネットワーク要件

- 送信: `wss://jetstream2.us-east.bsky.network:443` (フェイルオーバー先も同様)
- 送信: `https://public.api.bsky.app:443` (プロフィール取得)
- 送信: `https://cdn.bsky.app:443` (画像。モニター側ブラウザから直接取得する)
- 会場 LAN からサーバーの `:3000` へ到達できること (管理端末を別にする場合)

## 7. 終了後

1. サーバーを `Ctrl+C` で停止する。
2. 投稿データはメモリ上のみで保持しているため、停止時点で破棄されます。
   記録が必要な場合はイベント前に別途エクスポート手段を用意してください。
