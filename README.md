# Bsky Live Wall

Bluesky の特定ハッシュタグ付き投稿を **Jetstream v2** からリアルタイム受信し、
イベント会場のモニター／スクリーンに大きく流し続けるライブウォールです。

- サーバーサイドで動作する Node.js アプリ 1 プロセスで完結します。
- 会場モニターはブラウザを全画面にするだけ。ページ更新なしで流れ続けます。
- Bluesky アカウントの認証情報は不要です (公開エンドポイントのみを使用)。

## 必要環境

- Node.js 20 以上 (開発は 24 で確認)
- pnpm (npm / yarn でも可)
- 会場 PC からインターネットへの WebSocket 接続 (`wss://jetstream*.bsky.network`)

## セットアップ

```bash
git clone <このリポジトリ>
cd bsky-live-wall
pnpm install
cp .env.example .env
```

`.env` の `HASHTAGS` をイベントのハッシュタグに書き換えます。

```dotenv
HASHTAGS=myevent2026
EVENT_TITLE=My Event 2026
EVENT_SUBTITLE=Tokyo / Hall A
```

## 起動

```bash
# 開発 (ファイル変更で自動再起動)
pnpm dev

# 本番
pnpm build
pnpm start
```

| URL | 用途 |
| --- | --- |
| `http://localhost:3000/wall` | **会場モニター用**。ブラウザで開いて F11 で全画面にする |
| `http://localhost:3000/admin` | 運営用の管理画面 |
| `http://localhost:3000/api/health` | ヘルスチェック |

## 会場モニターの操作

会場係が過去の投稿を遡って確認できます。

| 操作 | 動作 |
| --- | --- |
| マウスホイール / トラックパッド | 過去の投稿へスクロール |
| スクロール中に新着が届いた場合 | 読んでいる位置は動かず、画面下部に「N 件の新着」が出る |
| 「N 件の新着」をクリック | 先頭 (最新) へ戻る |
| 60 秒間操作しない | 自動で先頭へ戻り、新着への追従を再開する |

先頭にいる間は常に最新が追従表示されるため、通常の運用では操作は不要です。
遡れる範囲は `WALL_MAX_CARDS` (既定 40 件) までです。

## 会場モニターの表示オプション

URL クエリで `.env` の設定を上書きできます。

| クエリ | 例 | 説明 |
| --- | --- | --- |
| `columns` | `?columns=2` | カラム数 (`1` で縦流れ) |
| `max` | `?max=60` | DOM 上に保持する最大カード数 |
| `theme` | `?theme=light` | ライトテーマ |
| `noimages` | `?noimages=1` | 画像を表示しない |
| `demo` | `?demo=1` | ダミー投稿で表示確認 (リハーサル用) |

## 設定

すべて `.env` で指定します。項目の一覧と既定値は [`.env.example`](./.env.example) を参照してください。
主なものは以下です。

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `HASHTAGS` | `bskyevent` | 監視するハッシュタグ (カンマ区切りで複数可) |
| `KEYWORDS` | 空 | ハッシュタグ以外に監視するキーワード (本文の部分一致) |
| `KEYWORD_REQUIRE_APPROVAL` | `true` | キーワードだけで一致した投稿を承認待ちに回すか |
| `MODERATION_MODE` | `open` | `approve` にすると運営が承認した投稿だけを表示 |
| `NG_WORDS` / `NG_PATTERNS` | 空 | 除外する語 / 正規表現 |
| `BLOCK_ACTORS` | 空 | 除外する DID / ハンドル |
| `ALLOW_REPLIES` | `true` | リプライを表示するか |
| `FILTER_LABELED` | `true` | 成人向けラベル付き投稿を除外するか |
| `WALL_COLUMNS` | `1` | カラム数。`1` で縦に流れる。`2` 以上で横並びのグリッド |
| `WALL_MAX_CARDS` | `40` | DOM 上に保持する最大カード数。スクロールで遡れる範囲 |
| `ADMIN_TOKEN` | 空 | 管理 API のトークン。空の場合は localhost からのみ操作可。**リモート公開時は必須** |
| `TRUST_PROXY` | `false` | リバースプロキシ配下で `true`。実クライアント IP を判定し、トークンを必須にする |
| `ADMIN_SESSION_TTL_HOURS` | `12` | 管理セッションの有効時間 |
| `AUTH_MODE` | `token` | `oauth` で Bluesky アカウントによるログイン。`both` で併用 |
| `PUBLIC_URL` | 空 | OAuth 使用時に必須。公開 URL |
| `ADMIN_ACTORS` | 空 | 管理を許可するアカウント (ハンドル / DID)。招待制の実体 |
| `STARTUP_BACKFILL_MINUTES` | `120` | 起動時に遡って過去の投稿を拾う分数 |

## 仕組み

```text
Bluesky --(WebSocket: Jetstream v2)--> [ingest] タグ判定 -> モデレーション -> リングバッファ
                                                                       |
                                          [server] Fastify --(SSE)--> 会場モニター / 管理画面
```

- タグ判定は投稿レコードの `facets` (richtext tag)、`tags` フィールド、本文中の `#タグ` の 3 経路を
  NFKC 正規化 + 小文字化して照合します。日本語タグにも対応します。
- ハッシュタグ以外のキーワード (本文の部分一致) も監視できます。詳細は下記を参照してください。
- 投稿の削除 (`delete` コミット) を受信すると、会場モニターからも即座に取り下げ、
  ヘッダの表示件数からも差し引きます。運営が非表示にした投稿も同様です
  (復元すると戻ります)。画面の全消去では件数は減りません。
- 起動時は `STARTUP_BACKFILL_MINUTES` の分だけ過去に遡って再生し、開始直後から画面が埋まった
  状態にします。**この再生はライブ受信とは別の接続で並行して行う**ため、起動直後の新着投稿が
  遅れることはありません。詳細は [バックフィル](#バックフィル起動前の投稿を拾う) を参照してください。
- 投稿者のプロフィール (表示名・アバター) は公開 AppView から非同期に取得し、解決後に差分だけを配信します。
  取得できなくても投稿の表示は止まりません。

詳細は [docs/architecture.md](./docs/architecture.md) を参照してください。

## キーワード監視 (ハッシュタグ以外)

ハッシュタグに加えて、本文中の任意の文字列を監視できます。
管理画面で「キーワードとして追加する」にチェックを入れるか、`.env` に書きます。

```dotenv
KEYWORDS=基調講演,keynote
```

**ハッシュタグとキーワードは性質が違います。**

| | ハッシュタグ | キーワード |
| --- | --- | --- |
| 投稿者の意思 | 「この場に出す」と明示している | イベントを認識していない可能性がある |
| 一致方法 | タグの完全一致 | 本文の部分一致 |
| 既定の扱い | そのまま表示 | **承認待ちに回す** |

キーワード一致は、イベントを知らない第三者の投稿を会場スクリーンに映してしまう
可能性があります。そのため、**ハッシュタグが付いておらずキーワードだけで一致した投稿は、
既定で承認待ち**に入り、運営が承認したものだけが表示されます。

```dotenv
# 承認を挟まずに表示したい場合 (会場の性質をよく考えたうえで)
KEYWORD_REQUIRE_APPROVAL=false
```

キーワードは 2 文字以上、監視対象は合計 20 件までです。

## バックフィル (起動前の投稿を拾う)

サーバーを起動した時点より前の投稿も、Jetstream のカーソル再生機能で遡って取り込めます。
イベント開始前に告知タグで投稿してくれた人のコメントを、開場と同時に画面へ出せます。

```dotenv
STARTUP_BACKFILL_MINUTES=120
```

| 遡る時間 | 取り込み完了までの実測時間 |
| --- | --- |
| 60 分 | 約 27 秒 |
| 120 分 | 約 90 秒 |
| 180 分 | 約 76 秒 |

取り込みは**ライブ受信とは別の WebSocket 接続**で並行して行われます。ライブ側は起動から
約 1 秒で新着投稿を受け始めるため、バックフィル中でもリアルタイム性は損なわれません。
取り込んだ過去投稿とライブ投稿が重複した場合は URI で重複排除されます。

### 削除された投稿の扱い

**バックフィルで取り込んだ投稿のうち、既に削除されているものは表示されません。**

過去分は取り込みが完了するまでサーバー側で保留し、再生中に届いた削除を反映してから
まとめて会場モニターへ送ります。1 本の接続で順に流すと「表示された数十秒後に消える」
ちらつきが起きるため、この方式にしています。運営が管理画面で非表示にした投稿も同様に除外されます。

実測 (4 時間の窓、2498 件が一致): うち削除済み 39 件を除外し、表示した 2459 件は
AppView 照合で全件が実在することを確認しています。

過去分は会場モニターの**既存カードより下**に時系列順で積まれるため、
ライブで流れている最新の投稿が押し下げられることはありません。

- 上限は Jetstream 側の保持期間で、実測でおよそ **36 時間** です。それより古いカーソルを
  指定しても保持境界に丸められ、エラーにはなりません。
- 遡る時間に比例して追いつくまでの時間が延びます。イベント用途では 60〜180 分が実用的です。
- 追いつくまでの間もリアルタイム受信は並行して進むため、投稿を取りこぼすことはありません。
- 保持件数は `BUFFER_SIZE` (既定 200) で頭打ちになります。長時間のバックフィルで古い投稿まで
  残したい場合は `BUFFER_SIZE` も上げてください。
- `0` にすると無効化され、起動時点以降の投稿のみを表示します。

なお、Bluesky の検索 API (`app.bsky.feed.searchPosts`) を使えばより長期間の遡及が可能ですが、
公開エンドポイントでは認証が必要 (未認証だと 403) なため、本システムでは採用していません。

## カスタムフィード (任意機能)

`FEED_GENERATOR_ENABLED=true` にすると、AT Protocol のカスタムフィード
(`app.bsky.feed.getFeedSkeleton`) を公開します。参加者が Bluesky アプリからも同じタグを
追えるようになりますが、公開するにはグローバルにアクセス可能な HTTPS ホスト名と
`did:web` の設定、フィードの publish 作業が別途必要です。会場内だけで使う場合は不要です。

## リモートから使う (コンテナ / LXC)

サーバーで常時稼働させ、リモートから利用する場合の手順は
[docs/deployment.md](./docs/deployment.md) を参照してください。
Docker Compose (Caddy による TLS 自動取得)、Docker 単体、LXC + systemd の
3 通りの構成と、リバースプロキシの設定例を用意しています。

```bash
# 最短手順 (Docker Compose)
cp .env.example .env
# .env に HASHTAGS / ADMIN_TOKEN / WALL_DOMAIN を設定
docker compose up -d
```

リモート公開では、管理画面のログインを **AT Protocol OAuth** にできます。
共有トークンと違い、個人単位で識別・許可・失効ができます。

```dotenv
AUTH_MODE=oauth
PUBLIC_URL=https://wall.example.com
ADMIN_ACTORS=alice.bsky.social,bob.example.com
```

OAuth は本人確認までを担い、管理してよいかは `ADMIN_ACTORS` の許可リストで決めます
(招待制の実体)。スコープは `atproto` のみで、パスワードは本システムに入力されません。

**リバースプロキシ配下では `TRUST_PROXY=true` が必須です。** 設定しないと、
プロキシ経由のアクセスがすべて loopback と誤認され、`ADMIN_TOKEN` が空の場合に
誰でも管理 API を操作できてしまいます (このため `TRUST_PROXY=true` かつ
`ADMIN_TOKEN` 未設定では起動を拒否します)。

## アイコン

管理画面のアイコンには Font Awesome Free を使います。**CDN は参照しません。**
会場のネットワークが不安定でも確実に表示させるため、`pnpm build` / `pnpm dev` 実行時に
`node_modules` から `public/vendor/fontawesome/` へ複製して自前で配信します
(`scripts/vendor-assets.mjs`)。

`public/vendor/` は生成物のため git 管理外です。`pnpm install` 後に
`pnpm build`、`pnpm dev`、`pnpm vendor` のいずれかを実行すると作られます。

## テスト

```bash
pnpm test
```

タグ判定 (`src/ingest/hashtag-matcher.ts`) とモデレーション (`src/ingest/moderator.ts`) の
純粋ロジックを対象にした単体テストが `test/` にあります。ビルド成果物 (`dist/`) に対して実行します。
